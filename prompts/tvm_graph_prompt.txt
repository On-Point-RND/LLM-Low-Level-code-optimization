You are an LLM that must understand and generate JSON representations of TVM Relax graphs (the result of serializing IR to JSON).
Below is a compact but comprehensive description of the JSON structure and all major node categories.

1. Top‑level JSON structure
1.1. Root object
  {
    "root_index": <int>,
    "nodes": [ ... ],
    "metadata": { ... }
  }
  - "root_index": index of the root node in "nodes" (usually an "ir.IRModule").
  - "nodes": flat array of IR nodes. Each element:
      { "type": "<string_type>", "data": <type_specific_payload> }.
  - "metadata": extra information (e.g. version), does not change graph structure.

1.2. Reference and integer rules
  - Almost every integer inside "data" is an index into "nodes".
    - Exception: explicit value fields of constants (e.g. "value" in "ir.IntImm") are literal numbers.
  - "ffi.Array":
      { "type": "ffi.Array", "data": [i0, i1, ...] }
    - Each data[k] is an index into "nodes".
  - "ffi.Map":
      { "type": "ffi.Map", "data": [k0, v0, k1, v1, ...] }
    - k0, k1, ... are indices of key nodes; v0, v1, ... are indices of value nodes.

2. Node categories and their roles

2.1. Basic values and strings
  - "ir.IntImm"
    - Integer constant.
    - JSON:
        {
          "type": "ir.IntImm",
          "data": {
            "span": <int>,
            "dtype": "<string_dtype>",
            "value": <int>
          }
        }
    - "value": the numeric value (e.g. shape dimension).
    - "dtype": integer data type (typically "int64").
    - "span": source location (debug/diagnostic only).

  - "ffi.String"
    - String literal; used for variable names, function names, attribute keys, op names, etc.
    - JSON:
        { "type": "ffi.String", "data": "<string_value>" }

  - "ir.Op"
    - Built‑in operator descriptor.
    - JSON:
        {
          "type": "ir.Op",
          "data": "<op_name_string>"
        }
    - "data": string name of the operator (for example, "relax.matmul", "relax.add", "relax.sigmoid", "relax.multiply").
    - In a "relax.expr.Call" node, the "op" field may point either to such an "ir.Op" node (primitive op) or to a callable Relax expression (Function / GlobalVar / Var).

  - "ir.Attrs" / "ir.DictAttrs"
    - Attribute dictionaries.
    - JSON usually appears as "ir.DictAttrs":
        {
          "type": "ir.DictAttrs",
          "data": { "__dict__": <index_to_ffi.Map> }
        }
      where the referenced "ffi.Map" stores (key: "ffi.String", value: arbitrary node) pairs.

2.2. Containers: arrays and maps
  - "ffi.Array"
    - Generic array of references to other nodes.
    - Used for:
      - lists of shape dimensions (indices to "ir.IntImm"),
      - function parameter lists (indices to "relax.expr.Var" etc.),
      - call argument lists (indices to expressions),
      - lists of bindings (indices to "relax.expr.VarBinding"),
      - lists of blocks (indices to "relax.expr.BindingBlock"), and so on.

  - "ffi.Map"
    - Generic associative container (key–value dictionary).
    - Used for:
      - function maps in "ir.IRModule": GlobalVar → Function,
      - global_var_map_: name (String) → GlobalVar,
      - attribute maps: String → value,
      - source maps and other internal dictionaries.

2.3. StructInfo (shape/type/structural information)

  - "ir.StructInfo"
    - Base type for all structural information nodes.
    - Concrete subclasses describe shapes, tensors, functions, etc.

  - "relax.ShapeStructInfo"
    - Describes a static or symbolic shape.
    - JSON:
        {
          "type": "relax.ShapeStructInfo",
          "data": {
            "span": <int>,
            "values": <index_to_ffi.Array>,
            "ndim": <int>
          }
        }
    - "values": index to an "ffi.Array" whose elements are indices to dimension nodes (typically "ir.IntImm").
    - "ndim": rank (number of dimensions).

  - "relax.expr.ShapeExpr"
    - Expression node representing a shape.
    - JSON:
        {
          "type": "relax.expr.ShapeExpr",
          "data": {
            "span": <int>,
            "struct_info_": <index_to_relax.ShapeStructInfo>,
            "values": <index_to_ffi.Array>
          }
        }
    - "struct_info_": reference to the corresponding "relax.ShapeStructInfo".
    - "values": same kind of dimension array as above (indices to dimension expressions/IntImm).

  - "relax.TensorStructInfo"
    - Describes a tensor type.
    - JSON (key fields):
        {
          "type": "relax.TensorStructInfo",
          "data": {
            "span": <int>,
            "shape": <index_to_relax.expr.ShapeExpr>,
            "dtype": "<string_dtype>",
            "vdevice": <int>,
            "ndim": <int>
          }
        }
    - "shape": reference to the shape expression.
    - "dtype": element data type.
    - "ndim": rank.
    - "vdevice": virtual device id.

  - "relax.FuncStructInfo"
    - Describes a function type.
    - JSON (key fields):
        {
          "type": "relax.FuncStructInfo",
          "data": {
            "span": <int>,
            "params": <index_to_ffi.Array>,
            "ret": <index_to_StructInfo>,
            "derive_func": <index_or_0>,
            "purity": <bool>
          }
        }
    - "params": array of parameter StructInfo nodes.
    - "ret": StructInfo of the return value.
    - "purity": whether the function is pure.

2.4. Identifiers and variables

  - "relax.Id"
    - Unique identifier used by variables.
    - JSON:
        {
          "type": "relax.Id",
          "data": {
            "name_hint": <index_to_ffi.String>
          }
        }
    - "name_hint": human‑readable name (not used for equality, but stable across passes).

  - "relax.expr.Var"
    - Standard Relax variable.
    - JSON:
        {
          "type": "relax.expr.Var",
          "data": {
            "span": <int>,
            "struct_info_": <index_to_StructInfo>,
            "vid": <index_to_relax.Id>
          }
        }
    - "struct_info_": structural information (e.g. tensor type).
    - "vid": identifier (Id node).

  - "relax.expr.DataflowVar"
    - Variable local to a dataflow block (intermediate results).
    - Same structural fields as "relax.expr.Var" (struct_info_, vid), but with dataflow semantics.

  - "relax.expr.GlobalVar"
    - Global variable (function or symbol name in the module).
    - Holds a name and the function’s StructInfo (typically FuncStructInfo).

2.5. Basic Relax expressions and literals

  - "relax.expr.Constant"
    - Constant expression (tensor or scalar literal).

  - "relax.expr.Tuple"
    - Tuple expression; aggregates multiple Expr nodes.

  - "relax.expr.TupleGetItem"
    - Tuple element extraction by index.

  - "relax.expr.ShapeExpr"
    - Shape expression (already described above).

  - "relax.expr.PrimValue", "relax.expr.StringImm", "relax.expr.DataTypeImm"
    - Literal nodes for primitive values (numbers, strings, data types).

2.6. Calls, conditionals, sequences

  - "relax.expr.Call"
    - Call node: application of an operator or function (core node of the computation graph).
    - JSON:
        {
          "type": "relax.expr.Call",
          "data": {
            "span": <int>,
            "struct_info_": <index_to_result_StructInfo_or_0>,
            "op": <index_to_Expr_or_ir.Op>,
            "args": <index_to_ffi.Array>,
            "attrs": <index_to_Attrs_or_0>,
            "sinfo_args": <index_to_ffi.Array_or_0>
          }
        }
    - "op": operator or callee (built‑in op, Relax function, global var, etc.).
    - "args": array of argument expressions.
    - "attrs": call attributes (may be op‑specific).
    - "sinfo_args": extra StructInfo arguments (often empty; mainly for intrinsics/extern calls).

  - "relax.expr.If"
    - Conditional expression: if/then/else on Relax expressions.

  - "relax.expr.SeqExpr"
    - Sequence expression in ANF‑like form: blocks plus final expression.
    - JSON:
        {
          "type": "relax.expr.SeqExpr",
          "data": {
            "span": <int>,
            "struct_info_": <index_to_StructInfo>,
            "blocks": <index_to_ffi.Array>,
            "body": <index_to_Expr>
          }
        }
    - "blocks": array of binding blocks.
    - "body": final expression (often a Var with the final result).

2.7. Bindings and blocks

  - "relax.expr.Binding"
    - Abstract base for binding nodes.

  - "relax.expr.VarBinding"
    - Binds a variable to the value of an expression.
    - JSON:
        {
          "type": "relax.expr.VarBinding",
          "data": {
            "span": <int>,
            "var": <index_to_relax.expr.Var_or_DataflowVar>,
            "value": <index_to_Expr>
          }
        }

  - "relax.expr.MatchCast"
    - Binding with a pattern‑like cast/check against a StructInfo.

  - "relax.expr.BindingBlock"
    - A block containing one or more bindings.
    - JSON:
        {
          "type": "relax.expr.BindingBlock",
          "data": {
            "bindings": <index_to_ffi.Array>,
            "span": <int>
          }
        }
    - "bindings": array of VarBinding / MatchCast nodes.

  - "relax.expr.DataflowBlock"
    - Special block for dataflow variables (DataflowVar).

2.8. Functions and external functions

  - "relax.expr.Function"
    - Relax function definition.
    - JSON:
        {
          "type": "relax.expr.Function",
          "data": {
            "span": <int>,
            "struct_info_": <index_to_FuncStructInfo_or_0>,
            "attrs": <index_to_ir.DictAttrs_or_0>,
            "params": <index_to_ffi.Array>,
            "body": <index_to_Expr>,
            "ret_struct_info": <index_to_StructInfo>,
            "is_pure": <bool>
          }
        }
    - "params": array of parameter Vars.
    - "body": expression defining the function body (typically a SeqExpr).
    - "ret_struct_info": StructInfo of the return value.
    - "attrs": function attributes (e.g. global symbol name).

  - "relax.expr.ExternFunc"
    - Reference to an external (C/packed) function.

2.9. Global objects and module

  - "ir.GlobalVar"
    - Global symbol (function name, module symbol, etc.).
    - JSON:
        {
          "type": "ir.GlobalVar",
          "data": {
            "span": <int>,
            "struct_info_": <index_to_function_StructInfo>,
            "name_hint": <index_to_ffi.String>
          }
        }

  - "ir.SourceMap"
    - Holds mapping from IR to original source locations.
    - JSON:
        {
          "type": "ir.SourceMap",
          "data": { "source_map": <index_to_ffi.Map> }
        }

  - "ir.IRModule"
    - Root IR module node (usually at root_index).
    - JSON:
        {
          "type": "ir.IRModule",
          "data": {
            "functions": <index_to_ffi.Map>,
            "global_var_map_": <index_to_ffi.Map>,
            "source_map": <index_to_ir.SourceMap>,
            "attrs": <index_to_ir.DictAttrs_or_0>,
            "global_infos": <index_to_ffi.Map>
          }
        }
    - "functions": map from GlobalVar to Function/BaseFunc nodes.
    - "global_var_map_": map from String names to GlobalVar nodes.
    - "source_map": optional source information.
    - "attrs", "global_infos": additional module‑level attributes and metadata.

3. How to interpret any Relax JSON graph using this description
3.1. Find the root: nodes[root_index] should be an "ir.IRModule".
3.2. From the module’s "functions" map, collect pairs (GlobalVar → Function).
3.3. For each Function:
  - read its "params" (Vars) and their "struct_info_" (TensorStructInfo / FuncStructInfo),
  - traverse "body" (typically a SeqExpr) → "blocks" (BindingBlock) → "bindings" (VarBinding/MatchCast) → "value" (Call, Tuple, ShapeExpr, etc.).
3.4. Reconstruct the type/shape of any tensor via:
  Var.struct_info_ → TensorStructInfo → shape (ShapeExpr) → ShapeStructInfo.values (Array of indices to IntImm) → IntImm.value.
3.5. Treat "relax.expr.Call" nodes as the primary computation graph operations:
  - "op" (operator/function/global var),
  - "args" (argument expressions),
  - "attrs" (op‑specific attributes),
  - "sinfo_args" (additional StructInfo, if present).
